<h1>Трекинг LLM-инференса с vLLM</h1>
<h2>Структура репозитория </h2>
run_vllm - запуск vllm<br>
1test_query.py - тестовый запрос к vllm<br>
2llm_evaluator.py - эксперимент с сохранением метрики<br>
samples - датасет для эксперимента<br>
screenshot - скрины mlflow<br>
<h2>Эксперимент с моделью</h2>
1) Просим локальную vllm модель(deepseek-ai/deepseek-coder-1.3b-instruct) объяснить что делает указанный фрагмент кода на с++.<br> 
2) Пересылаем ответ локальной модели LLM в роли оценщика(gigachat) и запрашиваем при этом оценку качества работы локальной модели от 1 до 10<br>
3) Сохраняем оценку для каждого фрагмента программы с++ в качестве метрики<br>
4) После обработки всех файлов датасета считаем среднюю, минимальную и максимальную оценку<br>
<h2>Как работает метрика</h2>
Оценка кастомной метрики LLM-as-a-Judge может быть в дальнейшем использована для сравнения качества оценки исходных кодов различными локальными моделями, либо в рамках одной модели с разными параметрами.
<h2>Выводы</h2>
В этом ДЗ мы освоили полный цикл использования LLM в роли оценщика (LLM-as-a-Judge): от развёртывания собственной модели через vLLM, до настройки кастомной метрики оценки качества ответов с помощью MLflow. 
Мы научитесь вызывать модель через OpenAI-совместимый API, формировать запросы на оценку и анализировать поведение модели в роли "судьи".
